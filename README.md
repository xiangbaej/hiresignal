# HireSignal

**채워지지 않는 채용 공고에서 외주 발주 신호를 찾습니다.**

어떤 회사가 Kubernetes 엔지니어를 750일째 못 구하고 있다면, 그 일은 어딘가에서 처리되어야 합니다. HireSignal은 공개 ATS API와 Wayback 아카이브를 결합해 그런 공고를 찾아 프리랜서·1인 에이전시의 리드로 변환합니다.

**[→ 현재 리드 목록 보기](https://xiangbaej.github.io/hiresignal/)**

---

## 어떻게 판단하는가

```
공개 ATS API (Greenhouse / Lever / Ashby / SmartRecruiters)
        ↓  일 1회 스냅샷 (관측 원장은 append-only)
Wayback CDX 로 개별 공고의 과거 존재 증명
        ↓
상시 공고 제외 → 수임 불가 직군 제외 → 신호 스코어링
        ↓
리드 목록 (근거 포함)
```

핵심은 **ATS가 보고하는 게시일을 신뢰하지 않는다**는 점입니다.

회사가 requisition을 재사용하면 게시일이 수년으로 부풀려지고, 반대로 초기화되기도 합니다. 실측된 사례에서 ATS는 `3일 전 게시`라고 표시했지만 같은 URL이 아카이브에는 `427일 전`부터 존재했습니다. 또 `updated_at`은 개별 편집이 아니라 보드 전체 일괄 갱신 값이어서 신호 가치가 없습니다 — Stripe 540건 중 84%가 동일 타임스탬프였습니다.

그래서 나이의 1차 근거는 **제3자 아카이브**입니다. 특정 공고 URL이 캡처되어 있으면 그 시점에 존재했다는 반증 불가능한 증거가 됩니다. 404 캡처를 증거로 오인하지 않도록 응답 상태코드까지 확인합니다([검증 스크립트](src/scripts/audit-archive-evidence.ts)).

## 신호 구성

| 신호 | 배점 | 근거 획득 시점 |
|---|---:|---|
| 관측 경과 (스냅샷 + 아카이브 하한) | 35 | 아카이브가 있으면 즉시 |
| 재게시 (닫힌 뒤 새 ID로 재등록) | 20 | 자체 관측 누적 필요 |
| 집중 채용 (동일 스택 계열 비중) | 20 | 즉시 |
| 게시일 리셋 (아카이브 > ATS 게시일) | 10 | 아카이브가 있으면 즉시 |
| 게시일 참고 | 5 | 즉시 |
| 재오픈 / 채용 증가율 | 10 | 자체 관측 누적 필요 |

누락 신호는 0점으로 계산하고, 등급은 **비율·기여 신호 개수·신뢰도를 모두** 요구합니다. 신호 하나로는 어떤 등급도 확정되지 않습니다. 신뢰도 50% 미만에서는 Hot을 부여하지 않습니다.

> 초기 구현에서는 누락 신호의 배점을 남은 신호로 재분배했는데, "신호가 적을수록 만점받기 쉬운" 역전이 발생했습니다. 전체의 95%가 warm으로 뭉쳐 등급이 판별력을 잃었고, 재정규화 방식을 폐기했습니다.

## 걸러내는 것

- **상시 공고** — "General Application", "Talent Community" 등은 특정 자리를 채우려는 게 아닙니다. 게시일 365일 초과도 requisition 재사용으로 간주합니다.
- **수임 불가 직군** — 영업·관리·고객지원·인사·재무 공고가 750일 막혀 있어도 프리랜서 개발자가 수임할 수 없습니다. 신호의 정확성과 리드의 유용성은 다른 축입니다.
- **회사 배경 태그** — 보드 내 40% 초과 등장하는 기술 태그는 회사 소개에서 온 것입니다(Databricks 802건 중 `spark` 511건). 클러스터 신호에서 제외합니다.
- **대기업** — 공고 150건 초과 보드는 조달 프로세스가 있어 콜드 아웃리치가 전환되지 않습니다. 실측 근거: 대기업 보드 2,663건 중 `freelance` 표현이 1건이었습니다.

## 실행

```bash
npm install
npm run boards:discover      # ATS 보드 발굴 (--write 로 시드 반영)
npm run enrich               # Wayback 아카이브 보강
npm run scan -- --report --export
npm run report:html          # data/report.html + docs/index.html

npm run ledger:check         # 커밋 전 필수 — 관측 원장이 줄지 않았는지 확인
npm run ui:test              # 리포트 UI 행동 테스트 (jsdom)
npm run roles:audit          # 직무 병합이 무엇을 놓쳤는지 감사
```

`ui:test`는 생성된 `data/report.html`을 jsdom에 올려 인라인 스크립트를 실행하고, 실제 클릭과
키입력을 보내 화면 상태를 읽습니다. 정적 검사로는 부족하다는 것이 실측으로 확인됐습니다 —
`.feed{display:flex}`가 `[hidden]`을 덮어 두 피드가 동시에 렌더된 것, 보기 전환이 Hot·미연락
필터를 꺼뜨린 것, `j`가 정렬된 화면에서 엉뚱한 카드로 튄 것, 초안을 열면 키보드로 빠져나올 수
없던 것 모두 "클릭하고 결과를 본다"로만 잡혔습니다. [일일 워크플로우](.github/workflows/daily-scan.yml)의
커밋 스텝 앞에 걸려 있어 상호작용이 깨진 산출물은 배포되지 않습니다.

> **`data/`를 커밋하기 전에 `npm run ledger:check`를 돌리세요.** 원장은 append-only이므로
> 줄이 사라지면 그 관측은 되돌릴 수 없습니다. 2026-07-31에 봇이 커밋한 관측 5,558줄을
> 스테일한 작업트리가 덮어써서 유실된 사고가 있었고, 이 검사가 그 패턴을 잡습니다.
> [일일 워크플로우](.github/workflows/daily-scan.yml)의 커밋 스텝 직전에도 걸려 있습니다.

비밀값이 필요하지 않습니다. 4개 ATS와 Wayback CDX 모두 인증 없는 공개 엔드포인트입니다. `.env`는 성능 튜닝 값만 담습니다([예시](.env.example)).

[일일 워크플로우](.github/workflows/daily-scan.yml)가 매일 자동 실행됩니다.

## 데이터 취급

- **공고 본문을 재배포하지 않습니다.** 제목·회사·URL·파생 태그만 보관하고 모든 링크는 원문으로 연결합니다. 우리가 만드는 가치는 본문이 아니라 "어느 공고가 왜 기회인가"라는 판단입니다.
- **개인정보를 수집하지 않습니다.** 채용 담당자 연락처를 저장하지 않습니다.
- **보수적 호출 빈도** — 보드는 일 1회, archive.org는 동시성 3에 실행당 시간 예산을 둡니다.

### 제외 요청 (opt-out)

채용 담당자시라면 [이슈를 열어](https://github.com/xiangbaej/hiresignal/issues/new?title=Opt-out%20request) 회사명 또는 채용 보드 URL을 알려주세요. [`seeds/blocklist.json`](seeds/blocklist.json)에 추가되고, 다음 실행에서 **누적된 관측 데이터까지 삭제**됩니다. 수집만 중단하고 과거 데이터를 남기지 않습니다.

이 경로는 문서가 아니라 코드로 강제됩니다 — [`src/lib/blocklist.ts`](src/lib/blocklist.ts)가 발굴·스캔 양쪽에서 참조하고, 제외된 보드는 활성 목록에서 빠지므로 `pruneBoards`가 관측을 정리합니다.

## 알려진 한계

- **아카이브 커버리지 약 37%.** 나머지는 증거가 없어 신뢰도를 낮춰 표시합니다. 증거가 없다는 것이 "새 공고"라는 뜻은 아닙니다.
- **인지도 편향.** 아카이브는 알려진 회사가 더 잘 남습니다. 리드가 그쪽으로 기울어집니다.
- **archive.org 단일 의존.** Common Crawl 백업을 검토했지만 URL당 월별 인덱스를 다수 조회해야 해 비용 대비 효익이 낮아 보류했습니다.
- **재게시·충원 신호는 시간이 필요합니다.** 아카이브가 나이는 부트스트랩하지만 "닫혔다 다시 열림"은 자체 스냅샷으로만 알 수 있습니다. Hot 등급 수가 현재 적은 것은 이 때문입니다.
- **막혀 있다는 것이 외주를 준다는 뜻은 아닙니다.** 접근할 근거를 주지만 수주를 보장하지 않습니다.
- **API 용법에 대한 판단.** ATS의 job board API는 회사가 자사 채용 페이지를 만들도록 제공된 것입니다. 명문 금지는 없으나 제3자 집계가 의도된 용법도 아니라고 봅니다. 그래서 본문 미재배포·원문 링크·opt-out 경로를 갖췄습니다.

## 구조

```
src/lib/ats/            4개 ATS 커넥터 + HTTP(재시도/백오프/동시성) + 정규화
src/lib/signals/        score / stack / evergreen / role
src/lib/store/          file-store(원자적 쓰기 + append-only 원장) / archive-cache
src/lib/blocklist.ts    opt-out 강제
src/lib/title-variant.ts 같은 직무의 중복 공고·지역 변형 판정
src/pipeline/           scan / enrich-archive / report-html
src/scripts/            boards:discover / 커넥터 검증 / 아카이브 증거 감사
                        / 원장 회귀 검사 / 직무 병합 감사 / UI 행동 테스트
src/types/              jsdom 최소 타입 선언 (lib 에 DOM 을 열지 않기 위해)
docs/index.html         공개 티저 (GitHub Pages, main /docs 브랜치 모드)
seeds/                  companies(검증된 보드) / candidates(추측) / blocklist
data/                   관측 스냅샷 · 아카이브 캐시 · 리드 산출물
```

### 리포트를 쓰는 법

`data/report.html`은 의존성 없는 단일 파일이라 `file://`로도 열립니다. 정적 문서지만 매일 쓰는
도구라서 앱처럼 동작합니다.

- **필터 상태가 주소에 저장됩니다.** 탭·검색어·정렬·Hot만·미연락만이 해시에 담겨 새로고침해도
  유지되고, 그 주소를 그대로 북마크하거나 공유할 수 있습니다. `pushState`가 아니라
  `replaceState`를 쓰므로 뒤로가기가 필터 되돌리기로 변하지 않습니다.
- **하루 루프를 키보드로 돕니다.** `j`/`k` 카드 이동, `d` 초안 열기, `Esc` 초안 닫고 카드 복귀,
  `m` 연락함 표시. 그 다음 `j`로 이어집니다. 보조로 `/` 검색, `0‒9` 탭, `v` 보기 전환,
  `h` Hot만, `u` 미연락만, `s` 정렬 순환, `?` 도움말.
- **연락한 회사를 표시할 수 있습니다.** 이 리포트의 최종 목적은 콜드메일인데 "이미 보낸 곳"을
  알 방법이 없으면 같은 회사에 두 번 연락하게 됩니다. 서버가 없으므로 `localStorage`에 담습니다.
  표시한 회사는 목록에서 지우지 않고 옅게 내립니다. 무엇을 이미 했는지도 정보이고, 되돌리려면
  카드가 보여야 합니다. 공고별 보기에서도 같은 표시가 보입니다 — 안 보이면 표시를 만든 이유가
  사라집니다.
- **연락 이력을 백업할 수 있습니다.** 손으로 쌓은 기록이 브라우저 하나에 갇혀 있으면 캐시를
  비우는 순간 사라집니다. `?` 도움말 안에서 JSON으로 담고 되붙일 수 있습니다. 가져오기는
  덮어쓰지 않고 **합칩니다** — 지금 기기의 표시를 날려 버리면 복구할 수 없습니다.

`file://`에서는 `localStorage`와 `history.replaceState`가 막히는 브라우저가 있습니다. 모든 접근을
`try`로 감싸 두었으니 저장이 안 되더라도 필터·정렬·초안은 그대로 동작합니다.

두 화면 모두 `prefers-color-scheme`을 따릅니다. 색은 전부 토큰이며 선언부에 하드코딩된 색상이
없어야 합니다 — 하드코딩하면 다크 모드에서 조용히 깨집니다. 특히 솔리드 배경 위의 글자는
`--on-fg` / `--on-primary` / `--on-hot`을 쓰세요. 다크에서는 그 배경들이 밝아지므로 흰 글자를
직접 넣으면 읽히지 않습니다.

### 같은 직무의 중복 공고

회사는 한 자리를 여러 건으로 올립니다. cresta의 `Infrastructure Engineer/SRE`는 305일·157일·157일
세 건이 따로 올라와 있습니다. 이걸 세 줄로 나열하면 "직무가 세 개"로 읽히지만 실제로는
**한 직무에 자리가 세 개**이고, 이 구분이 제안 논지를 바꿉니다 — "여러 분야를 못 뽑는다"보다
"이 한 자리를 세 번 시도하고도 못 뽑았다"가 더 강한 근거입니다. 그래서 리포트는 `×3` 배지로
접고 개별 공고 링크는 전부 남깁니다.

지역만 다른 변형(`Staff Design Engineer - Americas / Canada / EU`)도 같은 직무로 묶되,
**접미사가 알려진 지역 표현일 때만** 묶습니다. 접미사를 무조건 떼면 서로 다른 직무가 합쳐지기
때문입니다 — scaleway의 `Software Engineer - Compute Marketplace`와 `- Kubernetes Specialist`는
형태가 같지만 다른 자리입니다. 잘못 접히면 자리 하나가 화면에서 사라지고, 그건 놓친 병합보다
비쌉니다. 어휘는 추측으로 늘리지 않고 [`npm run roles:audit`](src/scripts/audit-role-merge.ts)이
뽑는 미인식 접미사 빈도를 근거로만 넓힙니다. 실측 상위는 `engineer / ai / data / infrastructure`
처럼 전문분야어이고, 그게 정상입니다.

저장소는 인터페이스로 분리되어 있어 규모가 커지면 Postgres로 이관할 수 있습니다. 현재 파일 기반인 이유는 관측 시계를 하루라도 빨리 시작하기 위해서였습니다 — 60일 신호는 시작일이 늦어지면 그만큼 늦게 성숙합니다.
